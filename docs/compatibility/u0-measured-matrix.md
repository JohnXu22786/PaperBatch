# U0 compatibility matrix

Snapshot date: 2026-10-18. This is the current executor evidence record, not a support claim for a release.

## Evidence labels

Each probe record uses one status:

- `verified`: the stated measurement or test ran and returned the recorded evidence.
- `unavailable`: the needed engine, platform API, device, or executable was absent from the inspected environment.
- `blocked`: a measurement was attempted but access, policy, timeout, missing runtime dependency, or an unsupported binary prevented it. No policy denial occurred in this snapshot.
- `not-run`: the test was deliberately not attempted or needs an explicit fixture/opt-in. API export presence and simulator output never substitute for behavior tests.

The `source` field is `environment`, `native`, or `simulation`. G1 accepts only `verified` evidence with `source: native` for each required item.

## Dependency and ABI decision

The lab has a fixed evidence-handling rule: do not bundle a vendor binary or load a PDFium library during discovery. For a supplied PDFium DLL, record its path, size, SHA-256, file-version resource (when present), PE architecture, and relevant exported API names by reading the PE image. One native composition fixture now passes against the exact community binary in hosted Windows CI; bounded AcroForm/annotation behavior remains blocked, and the production PDFium distribution and ABI remain unpinned.

The production PDFium distribution and ABI are **not pinned yet**. The probe now keeps PDFium hashing, PE parsing, and version-resource lookup tied to one opened file identity, and reports the requested path separately from the target path resolved from that file handle. Office measurements use the same requested/target path distinction; Office/WPS trust and version metadata likewise use a stable path resolved from their locked file handle. The C# collector derives each Office/WPS/LibreOffice candidate's SHA-256 and PE/ELF architecture from one bounded read, so those fields cannot come from separate passes; that read is not an immutable snapshot against a concurrent in-place writer. For a direct C# LibreOffice engine, the post-version source digest is checked against the pinned launch snapshot; if in-place source mutation changes it, the identity and bitness rows are blocked. Linux runtime-directory selection rejects a replacement symlink entry and multiply linked engine files, so the engine's sibling runtime directory is unambiguous. Both launchers record and recheck a bounded sibling program-directory manifest after each command; it detects persistent file changes but does not make the tree immutable or cover dependencies resolved outside that directory. Safe regular-file inspection is limited to Windows and Linux; unsupported operating systems report blocked inspections without opening unchecked paths. Python and C# Windows LibreOffice launches use the final engine path resolved from the open handle, and Linux launches remove inherited loader overrides while keeping the runtime directory bound to an open descriptor through launch. These Windows identity guards have not been exercised on Windows; the current identity race fixtures ran on Linux. The approved .NET 10 Windows x64 direction remains provisional; freeze the PDFium build, architecture, exports, and composition/forms call contract only after a licensed Windows test confirms the exact DLL and behavior. The smallest plan delta is to keep G1 open and defer the native dependency pin until that evidence exists.

## Reproducible commands

From the repository root:

```sh
python3 tools/probe_libreoffice_export.py --engine-binary /opt/codex/runtimes/codex-primary-runtime/dependencies/native/libreoffice-headless/libreoffice/program/soffice.bin --expected-engine-sha256 d905a74dc92eaccb22481ba2de1345666a074a5f0d48322aaad1b6dc8a9e1e40 --output /tmp/paperbatch-u0-lo-evidence.json
python3 -m unittest tests/test_libreoffice_probe.py
docker --host=unix:///var/run/docker.sock run --rm --network none \
  -v "$PWD:/src" -w /src \
  mcr.microsoft.com/dotnet/sdk:10.0 \
  dotnet run --project tests/PaperBatch.CompatibilityProbe.Tests/PaperBatch.CompatibilityProbe.Tests.csproj -p:NuGetAudit=false
```

The first command requires the direct engine digest from the independently captured managed-runtime inventory, launches only that matching LibreOffice engine with fresh profiles, converts a generated local DOCX fixture, and stores JSON outside the repository. Do not calculate the expected digest from the candidate inside the same probe run. It does not alter default applications/printers, attach to or terminate an existing Office/WPS process, or submit a print job.
