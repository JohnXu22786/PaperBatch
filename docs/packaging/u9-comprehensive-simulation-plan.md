## Unit 5 delivery status: trusted Office/WPS contract and interactive harness

- `tools/office_wps_harness.py` checks the event, repository, protected `main` ref, exact checkout SHA and trusted workflow ref before constructing an adapter. It then requires an exact licensed ephemeral VM image/snapshot, one of the `office_only`, `wps_only`, or `coexistence` profiles with the expected software builds, isolated/reset profile metadata, explicitly empty repository-secret metadata, and the current approved deny-all network policy. Pull requests, forks, wrong metadata, and incomplete contracts return `blocked` before launch.
- The fixed operator script covers launch, opening an allowlisted synthetic document, PDF export, close, restart, and close again. A harness watchdog bounds each adapter call; timeout or cancellation invokes run-wide abort, which the trusted adapter contract requires to terminate a process even before launch returns and wait for run quiescence. Abort must complete successfully and the adapter worker must stop before cleanup proceeds. Adapter operations use an opaque stable process handle and must validate its identity atomically, so PID reuse cannot redirect a close or cancellation to another process. A returned launch handle is immediately marked for cleanup before cancellation or ownership checks. If abort quiescence, process termination, process ownership, or profile reset cannot be confirmed, the harness reports failure and preserves the run profile rather than controlling an unowned process or resetting/deleting data an adapter could still use. Tests exercise blocked calls, abort, unconfirmed abort, failed termination/reset, cancellation after launch, and ownership loss including PID reuse during a wait. Product selection must match the exact snapshot profile/build. The harness also checks run-local profile/output paths, export size, redacted reason codes, and bounded evidence. This module contains no Office COM or generic executable launcher. Every harness output is labeled `simulation_only` and has `compatibilityClaim: false`; a native adapter and licensed snapshot are not available here.
- `.github/workflows/u9-simulation-matrix.yml` runs the contract and harness stubs on a hosted Ubuntu runner. No self-hosted Office/WPS lane is enabled. Ordinary pull-request CI runs only the synthetic stubs.
