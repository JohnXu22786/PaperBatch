# U9 simulation qualification matrix

This matrix defines reproducible package and workflow checks for the unsigned Windows x64 lite beta candidate. Evidence from hosted runners, local containers, synthetic files, and simulated receivers is simulation evidence only. It does not close G1, G3 physical printing, or G4 real-use qualification. Observed results must be read from the exact commit's CI logs and retained artifacts; this document records the planned checks and known limits, not a generated per-run report.

## Package provenance fields

`package-manifest.json` records schema version, source commit, target/runtime, configuration, self-contained setting, both locked dependency-file digests, AGPL declaration, unsigned status, deliberately excluded engines/drivers/fonts, and the SHA-256 and byte length of every payload file other than `package-manifest.json` itself. The archive SHA-256 covers the manifest and all archive entries. The `.zip.sha256` sidecar hashes the archive. The verifier checks manifest shape, POSIX-relative and Windows-compatible names (including case-fold uniqueness), exact file set, hashes and sizes, archive entry count and uncompressed byte ceilings, special-file metadata, fresh extraction, required notices and archive sidecar. It validates all names, metadata, and declared sizes before creating its temporary extraction tree. Hashes detect accidental or deliberate byte changes only when the expected manifest/digest is trusted; the unsigned package is not authenticated by a publisher signature.

The Windows session report is a bounded snapshot record, not a host-wide audit. It records exact commit and package-manifest hash, runner provenance, scenario ID/status, deterministic before/after hashes and availability for selected read-only printer and current-user registry snapshots, and explicit limits. Its package comparison records the source revision and package manifest/archive hashes for each extracted tree and marks that the two trees are identical when they came from the same package. Raw registry values are not uploaded. It never submits a job or claims physical output. Session temporary files are rooted in the task-specific runner temp directory and removed before the report is written.

## Simulated package swap

The app stores persistent state under the current user's application data directory and uses versioned run/recipe schemas. The managed suite seeds a v1 SQLite schema with a legacy Ready job, verifies migration to the current schema, and injects a deterministic failure at the final migration step. It asserts the transaction restores the original schema version and preserves rows, then retries successfully and confirms no submission intent or transition was created. The test runs only against an isolated temporary database. Windows CI still switches between two extracted copies of the same current package; its report contains source revision and hashes that make this limitation machine-readable. There is no historical released package or supported installer/updater/rollback contract, so this is schema-migration evidence, not an application-version upgrade simulation. Source documents and unrelated directories remain outside the package tree and are treated as immutable inputs.
