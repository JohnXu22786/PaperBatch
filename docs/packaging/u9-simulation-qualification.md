# U9 simulation qualification matrix

This matrix defines reproducible package and workflow checks for the unsigned Windows x64 lite beta candidate. Evidence from hosted runners, local containers, synthetic files, and simulated receivers is simulation evidence only. It does not close G1, G3 physical printing, or G4 real-use qualification. Observed results must be read from the exact commit's CI logs and retained artifacts; this document records the planned checks and known limits, not a generated per-run report.

## Package provenance fields

`package-manifest.json` records schema version, source commit, target/runtime, configuration, self-contained setting, both locked dependency-file digests, AGPL declaration, unsigned status, deliberately excluded engines/drivers/fonts, and the SHA-256 and byte length of every payload file other than `package-manifest.json` itself. The archive SHA-256 covers the manifest and all archive entries. The `.zip.sha256` sidecar hashes the archive. The verifier checks manifest shape, normalized relative paths, duplicate paths, exact file set, hashes and sizes, ZIP entry safety, fresh extraction, required notices and archive sidecar. Hashes detect accidental or deliberate byte changes only when the expected manifest/digest is trusted; the unsigned package is not authenticated by a publisher signature.

## Simulated package swap

The app stores persistent state under the current user's application data directory and uses versioned run/recipe schemas. The managed suite covers current SQLite migration and recipe backward reads. Windows CI switches between two extracted copies of the same current package while preserving an isolated app-data fixture; this does not simulate a historical application version, migration, or supported rollback. Any future package-swap simulation must remain separate from installer support. Source documents and unrelated directories remain outside the package tree and are treated as immutable inputs.
